# /req: 先收集旧的业务逻辑

REQ 是 "当前功能的结论". 两种来源, 正文写法完全一样, 区别在状态与侦察对象:

| 来源 | 状态 | 内容从哪来 | 什么时候置 implemented |
|---|---|---|---|
| **已有业务** | 直接 implemented | 从代码反向整理出的现行规则 | 建立时就是 (它反映已实现的东西) |
| **全新业务** | draft | 讨论与草稿定下的**本期目标形态** | 立项 CR 落实时 (`/implement-cr` 段 C) |

全新业务的 REQ 只写本期要交付的形态 -- 想好但本期不做的能力写进第 2 节非目标 (叙述, 不编号),
别写成编号条目: implemented 的 REQ 里未带标注的条目即已实现, 写了不做就自相矛盾.

## 步骤

1. **定位与约定**. `../sdd/scripts/sdd.py` (相对本文件); 读约定 `../sdd/references/conventions.md`;
   读 `../sdd/references/writing-guide.md` -- 里面是好 / 坏条目的对照, 写之前过一遍.
2. **查重**. `sdd.py status` 看已有 REQ; 同一业务已有 REQ 就停: 改行为走 `/create-cr`, 只是订正直接
   改它并在变更记录追一行 "未改变既定行为". 一个业务只有一份现行 REQ.
3. **侦察, 记录到草稿**. `sdd.py new-draft <slug> req-recon` 建侦察记录 (性质: 侦察记录), 逐条带
   file:line. 这份记录是 review 车道 A 核对 REQ 的依据, 也是将来 CR 的起点 (立 CR 时自动并入 CR 目录).

   - **已有业务**: 侦察这个业务本身 -- 入口 (handler / worker), 状态机在哪 (状态常量, 迁移的守卫),
     规则表在哪 (判定函数, 决策分支), 约束 (CHECK, 触发器, 唯一键 = 幂等键), 队列 / 锁, 配置开关,
     现有测试覆盖了什么.
   - **全新业务**: 没有自己的实现可侦察, 改为侦察**接入面** -- 会复用哪些现有服务与表 (它们的约束
     和幂等语义决定了新业务能写什么), 相邻业务是怎么做同类事情的 (照抄既有模式比发明新的安全),
     有没有现成的开关 / 队列 / 锁会被新业务争用. 这些事实同时是立项 CR 第 3 节 "对现有系统的影响"
     的素材, 侦察一次两处用.
4. **建文件**: `sdd.py new-req <slug> "<业务名>"`. 编号由脚本分配, 不要手写.
5. **按模板逐节写** (`../sdd/assets/templates/req.md`, 每节的注释就是写法). 重点:
   - FR 一条一件事, "必须 / 不得", 只写业务语言; 表 / 字段在第 7 节, 文件在第 11 节.
   - 状态机画 mermaid + 迁移表, 每条迁移一个 BR; 组合条件用规则表, 自上而下首条命中.
   - AC 覆盖每条 FR 与关键边界, "给定什么输入, 看到什么结果", 带负例, 标注来源.
     已有业务的 AC 尽量对应到现有测试 (第 11 节测试行写文件名).
   - 5.4 写幂等 / 并发 / 未知结果 / 人工介入; 已接受风险写成结论 (论证不写).
   - 代码里读不出、需要人定的, 写进第 10 节开放问题, **不要编造规则**. implemented 的 REQ
     开放问题应为空 -- 读不出又必须有的, 先问用户.
6. **校验与索引**: `sdd.py validate` 到 0 错误 (警告逐条看), `sdd.py index`.
7. **汇报**: 文件路径, 条目数 (FR / BR / AC), 开放问题列表, 侦察记录路径.
   全新业务再提示下一步: `/create-cr <slug>` 立立项 CR (它会自动认出这是新业务).

## 不做

- 不改代码. 侦察发现现状缺陷 (比如工单只有打开路径没有关闭路径) 记进 5.4 "已知现状缺陷"
  作为结论, 修复另立 CR.
- 全新业务不在这里写实现方案 (那是 spec 的 §1/§2), 也不写 "为什么现在做" (那是立项 CR 第 1 节).
  第 11 节代码落点此时留空, 由 `/implement-cr` 落实时填.
- 正文不放 file:line, 不放推导, 不放 "为什么这样设计" -- 这些在草稿与将来的 review 里.
- 不手工编辑 INDEX.md.
